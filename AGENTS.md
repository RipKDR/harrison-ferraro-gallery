# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Home wall — 17 October 2026
User rejected the scroll-told home: too slow to reach the art, effects gimmicky, the quote opening didn't land, off on mobile. This supersedes the Exhibition scroll and Home refinement sections for `/` (their site-wide rules — labels, arrows, no middle dots — still hold). Built with the ScrollCraft "gallery / catalog" grammar: `/` is one gallery wall. "Harrison Ferraro" is lettered on the wall like exhibition vinyl, then all ten works hang in catalogue order as `WorkCard`s, then a closing plate set like a wall label carries the one Enquire button. Every canvas is 60 × 90 cm, so each `li` is `--wcm` (its width in cm) times `--cm` (one centimetre): the landscape canvas is 1.5× a portrait's width and every frame shares one centre line, labels hung below. `WalkMotion` pins the wall and turns vertical scroll into a walk along it (section height = wall width; layout is read only on measure, never in a scroll frame), keeps the index of titles at the foot of the stage current, makes the index and Tab walk to a painting, and marks the painting nearest the centre as the smoke source. Gallery spacing is 40 cm, with 80 cm of quiet wall before Red Breath, the peak (55 cm on a phone, where 80 cm is wider than the screen and left a screen of bare smoke). On a phone the name hangs above the wall so the first painting is on the first screen. Reduced motion or no script: the same markup is a still hang wrapping down the page. The statement stays on `/about`, verbatim. `three` is used for one thing only: `SmokeWall`, a fixed canvas under the grain. The smoke drifts at half the walk's speed, gathers around the current painting and rises off it, thicker at Red Breath (`data-smoke`), and never hangs below a frame, where the label is. User asked for stronger smoke on 17 October 2026: alpha is `uCap` (0.6) times the noise, so the thickest smoke keeps its texture instead of flattening into a grey sheet, which a clipped `min()` cap produced. Brightness goes with alpha squared (premultiplied output, then normal blending), which keeps thin smoke near-invisible and reads as wisps; correcting it to linear made a flat fog, so it stays. The smoke thins out as the wall scrolls away, so none hangs over the footer. On `/` the header wordmark is hidden (visibility, so the nav keeps its place) because the h1 already letters the name directly beneath it. The domain-warp fields use a 3-octave noise at gain 2.2, because the full 5-octave noise at gain 3 folded into jagged cliffs; measured on rendered pixels, every label, index link and plate link clears 4.5:1 at the peak, start and end of the wall. It never draws over or textures a painting; paintings stay `next/image`. It is lazy-imported (not in the initial bundle), half resolution with a sine-free hash (sin() hashing showed square blocks), paused in a hidden tab, absent with reduced motion or without WebGL, and disposed on unmount.

## 3D hall — 17 October 2026
User rejected the smoke wall and every sketch short of 3D: they want a stand-out, phone-first site built with Blender and three.js. This supersedes "Home wall" for `/` (its site-wide label, arrow and middle-dot rules still hold); the smoke wall is kept on branch `wip/home-wall`. `/` is a hall of ten pointed-arch stone niches, one painting each. `scripts/blender/build-room.py` builds the room headless (`blender -b -P scripts/blender/build-room.py -- preview|bake`; Blender 5.2 at `C:\Program Files\Blender Foundation\Blender 5.2`, Cycles on the Intel GPU via oneAPI), bakes all light into `public/room/*.webp` and exports `room.glb` plus `hang.json` (hang positions, read from `src/artworks.ts`). Re-run the bake after changing the catalogue order or orientation. The room is drawn unlit (MeshBasicMaterial with the baked map), so a phone does no lighting maths; light maps are baked at 2× and scaled back by `EXPOSURE` for 8-bit precision. Paintings are never in Blender: `hall-scene.ts` hangs the photos on 2.5 cm canvases, unlit and untoned, and the camera never shows one above its native pixel size. One viewing distance for the hall (a portrait fills 44% of the height), so it never zooms between paintings. Drag or swipe sideways, wheel or arrow keys walk the hall; the wheel releases the page at either end, and vertical swipes always scroll the page. Tapping the current painting opens its work page. The markup under it is a still viewing room (one painting per screen, scroll-snapped), which is what reduced motion, no WebGL and crawlers get. Paintings are protected from casual saving only (`ProtectArt`: no right-click or drag on `.art`, no long-press, hidden in print); a screenshot cannot be blocked and the site never claims otherwise.

Prints are back (user, 17 October 2026): each painting gets a signed limited edition of 10 prints at a third of the original's price. This supersedes "Prints are removed" in the Portfolio direction section. Design first; the purchase flow is not built yet.

## Cursor Cloud specific instructions

`npm ci` is the install. Next.js 16 needs Node 20.9 or newer; the default image already has a new enough Node. There is no database and no extra system package. `npm run dev` serves the gallery on port 4173. Open `http://localhost:4173` or `http://127.0.0.1:4173` — both hosts are in `allowedDevOrigins`, so the dev hot-reload socket connects. Resend, PostHog, and search-console keys in `.env.example` are optional; without `RESEND_API_KEY` and `ENQUIRY_TO_EMAIL` the enquiry and studio-list forms use the mailto fallback. Verify with `npm run typecheck`, `npm run lint`, `node --test tests/portfolio-routes.test.mjs` while the dev server is up, then `npm run build` and `npm run test:sites`.
