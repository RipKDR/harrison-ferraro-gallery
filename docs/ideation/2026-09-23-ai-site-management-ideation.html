AI that manages the Ferraro gallery — for traffic and print sales

Date: 2026-09-23 Topic: ai-site-management Focus: Claude / ChatGPT with meaningful management access Mode: repo-grounded

Yes — you mean an AI that acts like staff for the site: helping visitors, keeping the catalogue honest, growing discovery, and preparing print sales — without pretending you already have a shop or inventing prices. The strongest path is not one chatbot with the keys to everything. It is a Studio Manager with full visibility and PR-gated write access, plus a tightly sealed visitor concierge.

Grounding Context

Codebase context. Next.js 16 App Router static export with a Three.js spatial hero (featured works 10→11→12) and a 12-work catalogue in src/artworks.ts. Enquiries are client-side mailto drafts to the authorised Gmail address; visitors must send. Prints are explicitly “in preparation.” Site is private preview with robots: noindex. No analytics, payments, or backend. Content changes require commit + rebuild + Sites packaging. Original photos only — no AI repainting.

Past learnings. None in docs/solutions/.

External context. Art/print chat that wins (e.g. Art Ilk) needs live catalogue + checkout — not available here yet. Static sites fit PR-gated content agents better than live CMS plugins. Industry pattern for “AI manages my site” is draft-only / approval queues / least privilege — not a single admin key. GEO/AEO needs text layers and real URLs; Instagram is the near-term traffic door while noindex stays on.

Idea 1 · Top pick

Studio Manager Stack — full visibility, PR-only authority

Give Claude/ChatGPT (as a studio ops agent) read access to catalogue, commercial plan, launch blockers, and build scripts — and write access only via git PRs that still run npm run build and test:sites. Publish a capability charter: it may propose copy, metadata, and launch checklist diffs; it may never invent prices, flip indexing alone, change contact details, touch artwork pixels, or claim a shop. That is the honest version of “full access”: full situational awareness, bounded power.

trust and permissions

Basis. direct: static export + Sites handoff constraints; robots noindex until human launch criteria; catalogue drafts in artworks.ts. external: PR-gated static agents (PullPress / Branchpost pattern); draft-only CMS agent guardrails.

Rationale. Answers “manage my site with full access” without giving an LLM silent production authority — the failure mode that burns artist reputation.

Downsides. Needs a GitHub (or equivalent) agent workflow and your review time; not a “set and forget” autopilot.

Confidence: 88%Complexity: Medium
Idea 2

Showroom Concierge — never-quote visitor assistant

On-site assistant (Claude/ChatGPT widget or embedded chat) that acts as a gallery docent: navigates works, explains original vs print-interest lanes, helps complete destination for packing quotes, and builds the existing mailto draft. Hard seal: refuse prices, editions, availability inventions, and “message sent” claims. Visitor still presses Send in their email app.

visitor-facing assistance

Basis. direct: enquire form + draft review UX already teach “not sent yet”; print “in preparation” copy; no persistence. external: Asyntai-style never-quote commissions; Art Ilk ROI depends on live Shopify inventory you do not have yet.

Rationale. This is the public face of “AI on my website” — conversion help on the only live sales path (enquiry), without a fake storefront.

Downsides. Hallucination risk if seal is soft; static hosting may need a third-party embed or edge function; verifier noted this is higher risk than PR-only ops.

Confidence: 72%Complexity: Medium
Idea 3

Confirmation Packet pipeline for the 12 works

Ops agent’s first job is not SEO — it is closing the catalogue confirmation loop. For each work it builds a packet (current descriptive label, reference number, featured status, missing medium/dimensions/availability/price rights) and proposes PR diffs to artworks.ts / statement copy only after you approve facts. Merge = confirmation.

content and catalogue ops

Basis. direct: draft labels and “confirmed before launch” copy; COMMERCIAL-PLAN launch item 1; stable IDs and featured order rules in AGENTS.md.

Rationale. Every traffic and sales idea after this is dishonest until titles and facts are ratified — this is the unlock.

Downsides. Still requires your confirmation sessions; agent cannot invent missing facts.

Confidence: 90%Complexity: Low–Medium
Idea 4

Instagram pace-note growth (traffic without indexing)

While the site stays noindex, treat Instagram as the front door. The Studio Manager writes “pace notes” per post: which work reference, which #work-id deep link, UTM recipe for bio/stories, enquire CTA language already on site. No analytics SDK until consent policies exist — still learn from which reference numbers show up in enquiry emails.

discovery and traffic

Basis. direct: Instagram authorised and linked; COMMERCIAL-PLAN plans UTM attribution; Instagram webview QA still outstanding; hash deep links already work.

Rationale. Fastest path to more print interest and original enquiries without prematurely opening Google to draft catalogue copy.

Downsides. Manual posting still on you; attribution is imperfect until analytics land.

Confidence: 85%Complexity: Low
Idea 5

Addressable work pages prepared under noindex

Keep the spatial hero on /, but generate static /works/work-10/-style pages from artworks.ts for shareable URLs and future SEO/GEO. Leave robots noindex until the launch gate is green. Agent drafts per-work metadata only from approved fields.

discovery and traffic

Basis. direct: hash-only deep links today; CODEX-HANDOFF calls for independently addressable artwork pages; Sites SPA fallback can coexist with real HTML files.

Rationale. Compounding traffic asset: each painting becomes a durable landing surface for Instagram, later search, and AI citations.

Downsides. Build/routing work; must not publish draft titles to the open web early.

Confidence: 82%Complexity: Medium
Idea 6

Private dual-inventory ledger + print proof agenda

Public site stays enquiry-only with “prints in preparation.” Privately (not in the static export), track interest by work reference and draft a proof agenda (which image first, two proportional sizes) from COMMERCIAL-PLAN — still no edition numbers or prices on the site until you approve. When merchant checkout arrives later, wire SKUs from this ledger rather than inventing a shop shell now.

commerce and sales path

Basis. direct: prints not orderable; proof-before-checkout plan; no fabricated fulfilment. reasoned: demand sensing needs an ops surface because the site does not store visitors.

Rationale. Connects “grow print sales” to the real next commercial step (proof), not a fake Buy button.

Downsides. Needs a private place to log interest (inbox tagging, sheet, or CRM); not automatic from the static site alone.

Confidence: 78%Complexity: Medium
Idea 7

Spatial / Instagram fallback conversion path

When WebGL fails or Instagram’s in-app browser breaks the hero experience, ensure visitors still reach the collection, featured trio context, and enquire with work context — including mailto/clipboard rescue. Agent helps draft the fallback copy and a QA checklist; implementation is UX hardening more than a second chatbot.

visitor-facing assistance

Basis. direct: spatial unavailable messaging and GalleryFallback exist; Instagram/WebGL QA called out as outstanding.

Rationale. Your likely traffic arrives on mobile IG — losing those visitors silently kills enquiries before any AI sales pitch matters.

Downsides. Narrow; does not by itself grow reach.

Confidence: 80%Complexity: Low
